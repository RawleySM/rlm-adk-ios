monitoring service, assignment registry or proposal for a general deployment engine.

## The smallest path to a first live attempt

1. **Stage the authored research project.** Create/enroll the actual local Git
   project through the normal project/launch workflow. Add a README, bootstrap
   copies of this document and AB_CAMPAIGN, an attempt directory and a resource
   observation directory. Use an existing work-register interface where available;
   do not add host domain schemas. Verify the five pinned project pointers still
   resolve and preserve unpublished work and skills refs before cutover.
2. **Prepare real trial inputs.** Have the coding-agent preparer or the admitted
   Researcher's delegate inspect current readers/products, snapshot selected
   prayers/context, resolve exact package receipts, and create valid A/B launch
   authoring with separate trial stores/worktrees. The first declared research
   work is preparation of this pair, not a general pipeline rebuild.
3. **Qualify the actual routes and monitor load.** Select a real gateway policy
   and delegate availability for the outer pair, coordinator and trial. The launch
   document does not select model IDs. Verify the shared lifecycle owners match.
   Reuse the original timing qualification only if its exact contract still applies;
   otherwise run the existing no-trial qualifier. No arbitrary five-scope claim
   follows from a previous four-scope measurement.
4. **Candidate-source preflight and update.** Build/seal/preflight the draft with
   the selected main-line release and actual service environment; validate skill
   installation compatibility and route readiness. Then use the documented
   foreground `allocatorctl update --repo ... --commit ... --launch ...` during
   the owned interruption window. Do not carry the V1 seal forward or perform a
   full reset merely to get two new residents.
5. **Direct mail and start evidence.** Verify delivered instruction/steering,
   exact roster/assignments and direct mail/replies for each resident. Researcher
   should start preparing A/B from its initial steering, not wait for another
   approval or tell Steward to choose its campaign.
6. **Attended A as first integrated proof, then B.** Install/native/live acceptance
   can be completed by this bounded first attempt; a separate broad epic is not
   required. Arm the external owner's 60-second checks, capture resource evidence,
   exercise the existing native coordinator and inspect original reports/outcomes.
   A failure requires exact settlement and focused repair before B.

The previously prepared L01 proof is not claimed complete by this new campaign.
Map which original proof obligations A/B actually exercise; keep unexercised
topology-growth or recovery cases explicitly separate rather than adding unrelated
behavior to the scientific comparison or erasing a validation gap.

## Mail room: implemented path, no new intake layer

The existing instance mailbox accepts explicit resident recipients. The outer
Steward's parent relationship supplies no research approval gate. A parent notice
that Researcher received operator mail is informational only.

After the new instance is active, operator examples are:

```bash
allocatorctl inbox post --to rsch01 --file <research-coaching.md>
allocatorctl inbox post --to stwlab --file <resource-coaching.md>
allocatorctl inbox list --to-operator
```

These are operator examples, **not messages sent by this preparation**. Resident
replies use `send_message("operator", text, in_reply_to=message_id)`. Confirm both
mail delivery and the model's response. A queued message can be accepted during a
pause, but cannot cause a paused resident to act. The first cycle does not require
voice-portal Intake routing; do not silently send its requests to absent `intk01`.

## Missing piece 1: useful resource evidence without another service

**Existing subscription mechanism:** retained `runtime_events` on plane
`subscription_usage`, event `subscription_usage_snapshot`, plus existing checkpoint
usage sections. Codex has a non-inference account probe; Claude observations come
from actual delegate streams; Grok capacity is unsupported in this implementation.
Collection ownership, source age, reset identity and coverage must be inspected.
The outer, coordinator and trial may observe the same account; do not add their
percentages together or attribute an account delta exclusively to one trial.

**Observed source gap:** no general GPU-memory producer was found in the current
live-test/host/dashboard collectors. Other unrelated image-generation scripts
mention GPU memory; that is not a generic supervisor evidence path.

**First-run design:** the attending external owner takes read-only samples on the
actual selected inference hosts, using supported device/process counters (for
example supported `nvidia-smi` queries). Record timestamp, host/device, metrics,
units, process/model when observable, errors and coverage. Use baseline, fixed
approximately 60-second intervals and post-settlement observations. An unsupported
counter remains unknown; label any unified-memory alternative separately.

Retain raw observations outside trial mutable output and stage immutable per-trial
resource summaries under `research/resources/<attempt>/` with references. This
is an authored evidence artifact, not an invented provenance table or claim of
automatic checkpoint ingestion. The external owner reviews GPU observations while
the outer pair is paused. After restoration Steward reads staged evidence; the
owner may send an explicitly authorized resource-update mail or subsequent operator
coaching can point to it. No Researcher-to-Steward relay is required.

If native coordinator resource decisions need these samples during a trial, add
the smallest explicit original-evidence read/delivery path to its existing review
input and prove model visibility. A file existing on disk is not that proof. Do
not postpone a first externally attended experiment to build a general collector.

## Missing piece 2: capacity is coarse, and Steward pauses

Capacity target controls outer admission and cooperative branch holds. Existing
attachments may remain while contraction debt is recorded. One project can dispatch
several calls, and loaded GPU models can retain memory even after activity stops.
Therefore reducing target is not evidence of lower VRAM or exact physical release.

Initial resource policy: target one; no automatic upward ramp; reduce admission on
clear exhausted capacity/resource failure; reply to Rawley's direct coaching.
Ceiling two allows a later increase without changing the sealed ceiling. Raising
target does not increase the single allocator's exclusive experiment concurrency.
Host/model concurrency and trial-local project capacity must be controlled in
their own existing configurations and measured independently.

During a trial, the independent coordinator and external owner observe and stop;
Steward changes outer resource policy between trials. Continuous resource steering
while simultaneously keeping the entire outer runtime active would require a
different quiescence arrangement and qualification. It is deferred from this
initial architecture, not silently promised.

## Missing piece 3: sponsorship, cancellation and recovery

Reuse the accepted native request, origin attribution, saved handle and existing
independent coordinator. Keep one sponsor attachment through pause and reconcile
the outcome after restoration before release. Do not retire or reassign that owner
during this attended pair. `cleanup_pending` blocks another attempt.

Native start/inspect/outcome does not itself register an independent experiment as
an outer attachment's settlement dependency, and does not expose a native cancel
export. Initial cancellation uses the qualified external lifecycle owner. No new
assignment registry is needed. Broader unattended sponsor retirement/restart and
native cancellation are later focused extensions only if this bounded path proves
useful. Retain their gaps explicitly in Researcher_Open_Items.

## What to test if a code repair is necessary

Follow Retrace red/green with scoped integrated assertions in F6. Reuse existing
native request, mailbox, capacity and supervision carriers. A documentation/schema
check is not a reason to run the full suite. For source changes, assert actual
delivery and native behavior rather than that a new helper exists.

- Direct operator mail reaches each exact recipient once; the correct model sees
  it and produces the threaded reply. Research startup does not depend on a
  fabricated Steward acceptance message.
- Every configured project slot is held by Researcher; a second outer coordinate
  is refused at target one, can be admitted after a valid target-two change, and
  contraction preserves real attachment/settlement obligations.
- Any added resource read retains original source identity, age, units and unknown
  coverage; shared account observations are not added twice. If used for a native
  decision, actual request history proves the model received the evidence.
- Actual native initiation, independent rounds, original monitor results and
  decisions, real wakes, exact settlement/restoration and outcome consumption
  remain covered. Provider-fake checks do not establish GPU measurements or
  actual-provider latency; the attended trial supplies that layer.
